## Как учим тему

Каждую тему сначала пробуем объяснить своими словами. Затем исправляем ошибки и только потом записываем короткую карточку. Конспект — опора для проверки, а готовность проверяется ответом без него.

**English answer, 60–120 seconds:**

1. **Definition:** “A … is …”
2. **Main idea:** “The key idea is …”
3. **Example:** “For example, …” — формула, рисунок, короткий код или SQL.
4. **Conditions and limitations:** “This requires …” / “A limitation is …”

Затем один дополнительный вопрос: отличие от близкого понятия, граничный случай, сложность или применение. Пример воспроизводим на бумаге за 2–3 минуты. Для темы с несколькими частями отвечаем по каждой: например, rank **и** determinant, fixed-point **и** floating-point, finite **и** pushdown **и** Turing machines.

Трудную тему разбираем так: краткое объяснение на английском → объяснение на русском с аналогией при необходимости → термины на английском → самостоятельный английский ответ. Не учим длинный перевод наизусть.

**Оценка темы:** 0 — не могу начать; 1 — фрагменты или существенная ошибка; 2 — правильное объяснение с примером, но нужны подсказки; 3 — ответ и пример без подсказок плюс один дополнительный вопрос. После первого прохода ставим цель минимум 2 по всем темам; к защите стремимся к 3. Начальное состояние — «не проверено», а не 0.

Повторяем тему на следующий день и ещё раз перед защитой. Оценки 0–1 получают время в ближайшем блоке повторения. Случайные пары до воскресенья выбираем из пройденного; с воскресенья — из всех 44. Вероятности выпадения тем неизвестны, поэтому ни одну тему не исключаем.

### Формулировки диплома, которые нужно уточнить в устном рассказе

- В §6.3 экспорт описан как поиск каждого трека. В реализации поиск нужен только для треков с другой платформы; исходные ID целевой платформы переиспользуются.
- В §6.5 упомянут скрытый YouTube iframe. В текущем `PlayerService` для YouTube вызывается `setYtVisible(true)`, для остальных платформ — скрытие. Рассказ и демо должны отражать текущее поведение.
- В §7.3 тестирование описано очень кратко. В репозитории есть и backend unit/integration tests, и frontend regression tests. Подготовить реальные примеры; не утверждать, что проверены внешние сервисы end-to-end или измерено покрытие.
- Apple Music описываем как реализованную, но отключённую в UI интеграцию, согласно §6.5; основное демо строим на Spotify/YouTube.
- Диплом содержит сокращённые листинги. Перед показом открываем текущий код, чтобы не обещать поведение на основании только упрощённого примера.

## Пробная защита и продолжение работы в этом чате

Одна пробная защита: рассказ с таймером, демо, два вопроса по коду, две случайные темы с примером, затем обратная связь. Во время ответа не подсказывать; разбор — после завершения.

Оцениваем: техническую правильность, понятность английского, самостоятельность, пример и время. Отдельно записываем вопрос, который застал врасплох, и исправленный короткий ответ. Две понедельничные репетиции выбирают разные пары тем; короткие ежедневные проверки дают более широкий охват.

Чтобы продолжить, можно написать **«Начинаем день 1»** или **«Продолжаем подготовку к защите»**. Следующая сессия:

1. Прочитать этот план и трекер, учесть реально оставшееся время.
2. Попросить минутный ответ по-английски: “What problem does iko solve, and what is your main contribution?”
3. Разобрать архитектуру и темы первого дня по одному вопросу. Сначала слушать ответ, затем объяснять и проверять повторно.
4. Обновить в трекере только фактически проверенные темы; записать ошибки, дату повторения и место остановки.
